# CORS Header Rewriting - Implementation Changelog

**Version:** 1.1.0

**Feature:** CORS Header Rewriting

**Status:** Implementation Plan

## Problem Overview

When a browser makes cross-origin requests, it sends two key headers:
- **`Origin`**: The domain where the request originates (e.g., `https://myapp.com`)
- **`Referer`**: The full URL of the page making the request

Backend servers often implement CORS policies that **reject requests** if these headers don't match expected values. When using a proxy, the `Origin` header still points to the original frontend domain, which causes the backend to reject the request with CORS errors.

**Solution:**
1. Rewrite outgoing `Origin` and `Referer` headers to match the target server
2. Rewrite incoming `Access-Control-Allow-Origin` response header to allow the original origin

#### 3b. Request Hook - Rewrite Outgoing Headers

In `request()` method, add CORS header rewriting:

```python
def request(self, flow: http.HTTPFlow) -> None:
    # ... existing request ID and timing logic ...

    # CORS Header Rewriting
    if self._config.cors_rewrite:
        self._rewrite_cors_request_headers(flow)
```

**New helper method `_rewrite_cors_request_headers()`:**

```python
def _rewrite_cors_request_headers(self, flow: http.HTTPFlow) -> None:
    """Rewrite Origin and Referer headers to match target server."""
    target_origin = self._get_target_origin()

    # Store and rewrite Origin header
    original_origin = flow.request.headers.get("Origin")
    if original_origin:
        flow.metadata["sentinel_original_origin"] = original_origin
        flow.request.headers["Origin"] = target_origin
        log.debug(f"CORS: Rewrote Origin from {original_origin} to {target_origin}")

    # Store and rewrite Referer header
    original_referer = flow.request.headers.get("Referer")
    if original_referer:
        flow.metadata["sentinel_original_referer"] = original_referer
        new_referer = self._rewrite_referer_url(original_referer, target_origin)
        flow.request.headers["Referer"] = new_referer
        log.debug(f"CORS: Rewrote Referer from {original_referer} to {new_referer}")
```

**Helper method `_get_target_origin()`:**

```python
def _get_target_origin(self) -> str:
    """Get the origin to use for CORS rewriting."""
    if self._config.cors_origin:
        return self._config.cors_origin

    # Auto-detect from target URL
    parsed = urlparse(self._config.target)
    return f"{parsed.scheme}://{parsed.netloc}"
```

**Helper method `_rewrite_referer_url()`:**

```python
def _rewrite_referer_url(self, original_referer: str, target_origin: str) -> str:
    """Rewrite Referer URL, replacing origin but preserving path."""
    parsed = urlparse(original_referer)
    # Keep the path portion, replace the origin
    return f"{target_origin}{parsed.path}"
```

#### 3c. Response Hook - Restore Original Origin

In `response()` method, add CORS response header rewriting:

```python
def response(self, flow: http.HTTPFlow) -> None:
    # CORS Header Rewriting - Response (before logging)
    if self._config.cors_rewrite:
        self._rewrite_cors_response_headers(flow)

    # ... existing response processing logic ...
```

**New helper method `_rewrite_cors_response_headers()`:**

```python
def _rewrite_cors_response_headers(self, flow: http.HTTPFlow) -> None:
    """Rewrite Access-Control-Allow-Origin to allow original origin."""
    original_origin = flow.metadata.get("sentinel_original_origin")
    if not original_origin:
        return  # No original origin stored, skip

    if not flow.response:
        return

    allow_origin = flow.response.headers.get("Access-Control-Allow-Origin")

    # If Access-Control-Allow-Origin exists and is not wildcard, rewrite it
    if allow_origin and allow_origin != "*":
        flow.response.headers["Access-Control-Allow-Origin"] = original_origin
        log.debug(f"CORS: Rewrote Access-Control-Allow-Origin from {allow_origin} to {original_origin}")

    # Handle credentials case: if credentials allowed, origin must be specific
    if flow.response.headers.get("Access-Control-Allow-Credentials") == "true":
        flow.response.headers["Access-Control-Allow-Origin"] = original_origin
```

## CORS Headers Reference

| Header | Direction | Purpose | Our Action |
|--------|-----------|---------|------------|
| `Origin` | Request | Browser's origin domain | **Rewrite to target origin** |
| `Referer` | Request | Full URL of requesting page | **Rewrite origin portion to target** |
| `Access-Control-Allow-Origin` | Response | Origins allowed by server | **Restore to original origin** |
| `Access-Control-Allow-Credentials` | Response | Whether credentials allowed | No change (affects Allow-Origin handling) |
| `Access-Control-Allow-Methods` | Response | Allowed HTTP methods | No change needed |
| `Access-Control-Allow-Headers` | Response | Allowed request headers | No change needed |
| `Access-Control-Expose-Headers` | Response | Headers JS can access | No change needed |
| `Access-Control-Max-Age` | Response | Preflight cache duration | No change needed |

## Edge Cases Handled

### 1. No Origin Header Present
Some requests (simple GETs without JavaScript) don't include `Origin`. The rewriting logic skips if header is absent.

### 2. Preflight Requests (OPTIONS)
CORS preflight requests are `OPTIONS` requests. They are handled identically - rewrite Origin on request, restore on response.

### 3. Wildcard `Access-Control-Allow-Origin: *`
If backend returns `*`, leave it unchanged. Wildcard already allows all origins.

### 4. Credentials with Specific Origin
When `Access-Control-Allow-Credentials: true` is set, browsers require a specific origin (not `*`). We always set the exact original origin in this case.

### 5. Missing CORS Response Headers
If the backend doesn't send any CORS headers, we don't inject them. This could be a future enhancement (`--cors-inject` flag).

### 6. Referer Path Preservation
When rewriting Referer, we preserve the path portion:
- `https://myapp.com/page/form` → `https://api.example.com/page/form`

## Logging

CORS header rewriting is logged at DEBUG level when `--verbose` is enabled:

```
DEBUG: CORS: Rewrote Origin from https://myapp.com to https://api.example.com
DEBUG: CORS: Rewrote Referer from https://myapp.com/page to https://api.example.com/page
DEBUG: CORS: Rewrote Access-Control-Allow-Origin from https://api.example.com to https://myapp.com
```

The original header values are stored in flow metadata for response rewriting but are NOT logged to the traffic JSONL file (to keep logs clean).
