# Forward Proxy Mode - Implementation Changelog

**Version:** 1.1.0
**Feature:** Forward Proxy Mode
**Status:** Implementation Plan

---

## Problem Overview

SentinelProxy currently operates in **reverse proxy mode** only:
- User specifies a single `--target` URL
- All requests to the proxy are forwarded to that target
- Cannot capture traffic to multiple domains simultaneously

**The Issue:**
When a frontend (`dcgf.onrender.com`) makes API calls to a different backend (`l39s.onrender.com`), the reverse proxy only intercepts traffic to ONE of them. API calls to the other domain bypass the proxy entirely.

**Solution:**
Add **forward proxy mode** where the browser is configured to route ALL traffic through the proxy. This captures requests to any domain without requiring code changes.

## Architecture Overview

### Reverse Proxy Mode (Existing)

```
┌─────────────────────────────────────────────────────────────────────────────┐
│  REVERSE PROXY MODE (--target required)                                      │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  Browser ──► localhost:8080 ──► ONLY target server                          │
│                                                                              │
│  Example: --target https://api.example.com                                  │
│           All requests go to api.example.com only                           │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

### Forward Proxy Mode (New)

```
┌─────────────────────────────────────────────────────────────────────────────┐
│  FORWARD PROXY MODE (--forward, no target needed)                            │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  Browser (proxy configured) ──► localhost:8080 ──► ANY server               │
│                                       │                                      │
│                                       ├──► frontend.example.com             │
│                                       ├──► api.example.com                  │
│                                       ├──► cdn.example.com                  │
│                                       └──► any other domain                 │
│                                                                              │
│  Browser proxy settings: HTTP/HTTPS Proxy = 127.0.0.1:8080                  │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 1. Configuration (`config.py`)

**New field added to `ProxyConfig` dataclass:**

```python
forward_mode: bool = False  # True = forward proxy, False = reverse proxy
```

**Validation changes:**

```python
def validate(self) -> list[str]:
    errors = []

    # Target is required ONLY in reverse proxy mode
    if not self.forward_mode:
        if not self.target:
            errors.append("Target URL is required in reverse proxy mode (or use --forward)")
        elif not self.target.startswith(("http://", "https://")):
            errors.append("Target must start with http:// or https://")

    # ... rest of validation
```

**Logic:**
- In reverse mode: `target` is required
- In forward mode: `target` is ignored (requests go to their original destinations)

### 3. Proxy Engine (`proxy.py`)

**Changes to `_run_proxy()` method:**

```python
async def _run_proxy(self, target_host: str = None, target_scheme: str = None) -> None:
    """Run the mitmproxy instance."""

    # Configure mitmproxy options based on mode
    if self._config.forward_mode:
        # Forward proxy mode - no mode specification needed
        opts = options.Options(
            listen_host=self._config.listen_host,
            listen_port=self._config.listen_port,
            ssl_insecure=False,
        )
    else:
        # Reverse proxy mode - specify target
        opts = options.Options(
            listen_host=self._config.listen_host,
            listen_port=self._config.listen_port,
            mode=[f"reverse:{target_scheme}://{target_host}/"],
            ssl_insecure=False,
        )
```

**Changes to `run()` method:**

```python
def run(self) -> int:
    # ... existing setup ...

    if self._config.forward_mode:
        log.info("Mode: Forward proxy")
        log.info("Configure your browser proxy settings to use this proxy")
        # No target parsing needed
        asyncio.run(self._run_proxy())
    else:
        # Existing reverse proxy logic
        parsed_target = urlparse(self._config.target)
        target_host = parsed_target.netloc or parsed_target.path
        target_scheme = parsed_target.scheme or "https"
        log.info(f"Mode: Reverse proxy")
        log.info(f"Target: {target_scheme}://{target_host}")
        asyncio.run(self._run_proxy(target_host, target_scheme))
```

### 4. Addon CORS Logic (`addon.py`)

**Updated `_get_target_origin()` for forward mode:**

In forward mode, the target origin is determined from each individual request, not from a global config.

```python
def _get_target_origin_for_request(self, flow: http.HTTPFlow) -> str:
    """Get the target origin for CORS rewriting.

    In forward mode: derived from the actual request destination
    In reverse mode: derived from config.target or config.cors_origin
    """
    # If custom cors_origin is set, always use it
    if self._config.cors_origin:
        return self._config.cors_origin

    # In forward mode, derive from request
    if self._config.forward_mode:
        req = flow.request
        scheme = req.scheme
        host = req.host
        port = req.port

        # Include port only if non-standard
        if (scheme == "https" and port != 443) or (scheme == "http" and port != 80):
            return f"{scheme}://{host}:{port}"
        return f"{scheme}://{host}"

    # Reverse mode - use target
    parsed = urlparse(self._config.target)
    return f"{parsed.scheme}://{parsed.netloc}"
```

**Updated `_rewrite_cors_request_headers()`:**

```python
def _rewrite_cors_request_headers(self, flow: http.HTTPFlow) -> None:
    """Rewrite Origin and Referer headers to match target server."""
    target_origin = self._get_target_origin_for_request(flow)

    # Store and rewrite Origin header
    original_origin = flow.request.headers.get("Origin")
    if original_origin:
        flow.metadata["sentinel_original_origin"] = original_origin
        flow.request.headers["Origin"] = target_origin
        log.debug(f"CORS: Rewrote Origin from {original_origin} to {target_origin}")

    # ... rest unchanged
```

## CORS Rewriting in Forward Mode

### Request Flow

```
Browser                         Proxy                           Server
───────                         ─────                           ──────
Origin: http://localhost:8080
        ──────────────────────►
                                Origin: https://api.example.com
                                (rewritten to match destination)
                                        ──────────────────────►
```

### Response Flow

```
Server                          Proxy                           Browser
──────                          ─────                           ───────
Access-Control-Allow-Origin:
  https://api.example.com
        ──────────────────────►
                                Access-Control-Allow-Origin:
                                  http://localhost:8080
                                (restored to original)
                                        ──────────────────────►
                                                                ✓ Accepted!
```

## Edge Cases Handled

### 1. Mixed Mode Usage
If user specifies both `--forward` and `--target`:
- Show warning that `--target` is ignored
- Proceed in forward mode

### 2. Neither Mode Specified
If user doesn't specify `--forward` and doesn't provide `--target`:
- Show error with clear message about options

### 3. CORS Origin Override
`--cors-origin` takes precedence in both modes:
- If set, always use that value for CORS rewriting
- Useful when you know the expected origin

### 4. Non-Standard Ports
In forward mode, correctly handle non-standard ports in origin:
- `https://api.example.com:8443` → include port
- `https://api.example.com` (443) → omit port

## Browser Configuration Guide

When using forward proxy mode, users need to configure their browser:

### Chrome/Edge (Windows)
1. Settings → System → Open proxy settings
2. Manual proxy setup → On
3. Address: `127.0.0.1`, Port: `8080`

### Firefox
1. Settings → Network Settings → Settings
2. Manual proxy configuration
3. HTTP Proxy: `127.0.0.1`, Port: `8080`
4. Check "Also use this proxy for HTTPS"

### Certificate Installation
For HTTPS interception, install mitmproxy CA certificate:
1. Start proxy: `sentinelproxy start --forward`
2. Configure browser proxy
3. Visit `http://mitm.it`
4. Download and install certificate for your OS
